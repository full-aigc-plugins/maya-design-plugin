# 媒体验证与 SHA-256 契约

## 校验项

| 项 | 要求 | 实现 |
|---|---|---|
| 容器 | `mp4` | ISO BMFF box 解析 |
| 编解码 | `h264` / `avc1` | `stsd` 首条目 format 字段 |
| 尺寸 | ≥ 1×1 | `tkhd` 的 4.16 定点数右移 16 位 |
| 帧率 | > 0 | `mdhd` timescale |
| 时长 | ≥ 0 | `mvhd` duration / timescale |
| 大小 | ≤ 200 MiB | 即梦 DCC 协议上限 |
| SHA-256 | 64 位小写十六进制 | 分块读取（64 KiB） |

## 为什么不用 ffprobe

1. **无依赖。** ffprobe 未必安装；装了也未必在 PATH。
2. **可测试。** 直接解析 box 让离线测试可以手工构造最小 MP4。
3. **够用。** 回执只需要上表这几项，不需要完整的流分析。

## 文件稳定性

媒体验证前要确认文件已经写完。`detect_mutation` 用进程内的
`_StabilityTracker` 记录上一次探测的 `(size, sha256)`；
后续探测若发现变化，返回 `stable=False`。

首次调用恒为 `stable=True`（没有基线），所以调用方需要**两次探测**
才能判断稳定性——这是刻意的接口设计，避免把「首次读取」误判为「不稳定」。
